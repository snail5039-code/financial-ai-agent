# BACKEND-001 범위

기준일: 2026-08-29 KST

## 목표

`BACKEND-001`은 실제 FastAPI 백엔드를 만들기 전, 첫 구현자가 참고할 좁은 백엔드 1단계 기준을 확정하는 단계다. 이 문서 세트는 코드 구현이 아니라 다음 구현의 범위와 안전 기준을 나눠 고정한다.

다음 구현의 최소 목표는 `/api/health`와 로컬 fixture API 골격을 준비하는 것이다. 대시보드, 승인 대기, 근거 패킷 등 장기 API 후보는 `docs/fullstack/03-data-api-contract.md`를 참조하고, 이 단계에서는 전체 목록을 구현하지 않는다.

## 이번 문서 작업 범위

이번 `BACKEND-001-DOCS`에서 허용되는 범위:

- `docs/backend/` 인덱스와 주제별 문서 생성
- `/api/health` 계약과 로컬 fixture 공통 응답 원칙 문서화
- 다음 구현에서 만들 `apps/api` 예상 구조 문서화
- 실제 금융 연결 금지 기준과 검증 체크리스트 문서화
- 필요 시 `docs/fullstack/00-readme.md`, `docs/handoff/01-current-state.md`, `docs/handoff/02-active-roles.md`의 참조와 상태만 갱신

이번 문서 작업에서는 FastAPI 코드, `apps/api`, 패키지, React 코드를 만들지 않는다.

## 다음 구현 범위

다음 백엔드 구현 작업에서 다룰 수 있는 범위:

- `apps/api` FastAPI 프로젝트 골격 생성
- `/api/health` 라우트 생성
- 공통 응답 래퍼와 안전 플래그 스키마 정의
- 로컬 fixture 데이터를 담을 위치와 로딩 방식 준비
- 백엔드 테스트 위치와 기본 테스트 생성
- 실제 외부 연결이 없음을 확인하는 문자열 점검

## 비범위

`BACKEND-001` 문서 작업과 다음 1단계 구현 모두에서 다음을 하지 않는다.

- 실제 금융 데이터, 계좌, 주문, 체결, 공시, 시세, 환율 API 연결
- 운영 DB 연결
- AI 모델을 투자 판단 또는 주문 흐름에 연결
- 실제 주문, 매수, 매도, 송금, 체결 처리
- 인증, 개인정보 저장, 유료 서비스 연결
- React 화면 구조 변경
- 장기 API 전체 구현

## 현재 상태와 연결

React/Vite `apps/web`는 이미 존재하며 정적 목업 19개에 대응하는 19개 화면 이전이 완료되어 있다. FastAPI 백엔드는 아직 생성하지 않았다. 따라서 다음 구현은 기존 프론트 상태를 깨지 않고, 백엔드가 안전한 fixture 응답을 제공할 준비를 하는 데 집중한다.

## 성공 기준

- `/api/health`와 로컬 fixture API 골격의 책임이 분명하다.
- 모든 응답은 모의 데이터임을 드러내는 안전 필드를 포함한다.
- 실제 금융 행동으로 오인될 이름, 응답, 흐름을 만들지 않는다.
- 구현 후 검증자는 코드 생성 범위와 안전 경계를 독립적으로 확인할 수 있다.
