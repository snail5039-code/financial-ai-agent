# 검색 근거(RAG) 확장 계획

작성일: 2026-10-06 · 상태: 계획 (아직 안 함) · 기준 문서: [08-dev-order.md](08-dev-order.md) 4단계, [01-requirements.md](01-requirements.md) FR-40

RAG(Retrieval-Augmented Generation): 질문과 관련된 문서 조각을 먼저 찾아서 AI 답변의 근거로 쓰는 방식이다.
지금은 공시 본문만 쓴다. **뉴스, 투자 용어, 내 기록**을 근거로 더 쓸 수 있게 넓힌다.

## 2. 넣을 것

### 2-1. 뉴스 (FR-40 뉴스·공시 탭과 같이)

- **저장하는 것**: 제목, 언론사, 발행 시각, 1~2줄 요약, 원문 링크, 관련 종목. **기사 본문은 저장하지 않는다** (저작권, [AGENTS.md](../../AGENTS.md) 5장)
- **근거로 쓰는 법**: 제목·요약만 임베딩해서 찾는다. 답변에는 출처 ID(`news:<id>`)와 링크·발행 시각을 붙인다
- **사실과 보도 구분**: 같은 내용의 공시가 있으면 `공시 확인`, 없으면 `미확인 보도`로 표시한다. 검증 AI는 미확인 보도만으로 매수 근거를 세우면 지적한다
- **오래된 뉴스**: 기본 30일 안의 것만 검색한다. 답변에 "며칠 전 보도"인지 쓴다
- **출처 후보** (구현 전에 이용약관 확인, 지금 `미확인`):
  - 네이버 검색 API(뉴스): 제목·요약·링크를 준다. 하루 호출 한도 있음
  - 언론사 RSS: 제목·링크. 재배포 조건이 언론사마다 다르다
  - 공시는 이미 OpenDART에 있으므로 뉴스와 따로 둔다

### 2-2. 투자 용어 · 개념

- **내용**: PER, PBR, 부채비율, 분산투자, 매매 비용, 변동성, 지정가, 손절 등. 처음엔 50개 안팎
- **만드는 법**: 공공기관 금융용어사전을 참고해서 **우리가 직접 쉬운 말로 쓴다** (원문 복사 금지). 항목마다 참고한 출처를 적고, 사람이 검토한 뒤 넣는다
- **쓰는 곳**:
  - 사용자가 "PER이 뭐야?"라고 물을 때 (새 요청 종류 `explain`)
  - 퀴즈를 틀린 사람(`quiz_missed`)에게 분석 답변 끝에 관련 개념 한 줄 ([09-investor-profile.md](09-investor-profile.md) 4장)
  - 분석 답변에 나온 지표 옆에 짧은 풀이
- 용어는 많지 않아서 벡터 검색 없이 이름 일치로 먼저 찾고, 못 찾으면 벡터 검색을 쓴다

### 2-3. 내 기록 (지난 처리안·검증 결과)

- "지난번에 SK하이닉스 왜 반려됐지?", "이번 달에 뭐 샀지?" 같은 질문
- 이미 DB에 있는 `proposals`, `verifications`, `orders`를 쓴다. 새로 임베딩하지 않고 종목·기간으로 SQL 검색 → 필요하면 나중에 요약문 임베딩
- **그 사용자 기록만** 검색한다 (다른 사용자와 섞지 않음, NFR-05a)

## 3. 공통 규칙

- 근거마다 **출처 ID**를 붙이고, 검증 AI는 출처 ID로 원문(뉴스면 제목·요약)을 DB에서 다시 읽어 확인한다 (지금 공시와 같은 방식)
- 바뀌는 정보(뉴스, 시세)에는 기준 시각을 붙인다. 찾지 못한 것은 `미확인`이라고 쓴다
- 테이블은 종류별로 따로 둔다 (`news_items`, `glossary_terms`). 하나로 합치는 건 검색이 실제로 느려지거나 복잡해질 때 생각한다
- 임베딩 비용: 뉴스 제목·요약은 짧아서 하루 수백 건이어도 적다. 수집은 기존 매일 자동 수집(`run_daily`)에 붙인다

## 4. 순서 제안

MVP(1~8단계)가 끝난 뒤에 한다. 8단계 데모에 뉴스 탭이 필요해지면 2-1을 앞당긴다.

1. 투자 용어 (데이터를 우리가 만들어서 외부 약관 문제가 없음, 퀴즈 오답 안내와 바로 연결)
2. 내 기록 질문 (새 데이터 없이 SQL로 가능)
3. 뉴스 (출처 약관 확인 → 수집 → 뉴스 탭 S-20 → 분석 근거)

## 5. 아직 정할 것

- 뉴스 출처와 약관 (사용자 확인 필요)
- 용어 개수와 검토 방법
- `explain` 요청을 understand(요청 이해)에 넣을지, 조회 그래프 안에서 처리할지
