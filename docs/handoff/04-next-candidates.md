# 다음 화면 후보

다음 작업 번호는 `MOCKUP-017`이다. `MOCKUP-015` 세금·수수료 영향 점검과 `MOCKUP-016` 사용자 승인 이력·결정 회고는 완료됐으므로, 아래 후보는 다음 기획자가 검토할 후보 목록이다.

## 완료: 세금·수수료 영향 점검

- 목적: 매수·매도 제안 전 수수료, 세금, 슬리피지, 예상 순손익이 어떻게 달라지는지 화면용으로 점검한다.
- 완료 파일: `tax-fee-impact.html`, `tax-fee-impact.css`, `tax-fee-impact.js`, `tax-fee-impact-1440x900.png`
- 검증: `MOCKUP-015-V` 대체 독립 검증 조건부 통과 후 README R1 재검증 `통과`
- 안전 경계:
  - 화면 검토용 가상 예시
  - 실제 세금 계산 아님
  - 실제 주문 아님
  - 실제 계좌·API·DB 미연결

## 완료: 사용자 승인 이력·결정 회고

- 목적: 사용자가 왜 승인·반려했는지, 이후 가상 결과가 어땠는지 돌아본다.
- 완료 파일: `decision-review.html`, `decision-review.css`, `decision-review.js`, `decision-review-1440x900.png`
- 검증: `MOCKUP-016-V` 대체 독립 검증 실패 후 R1 재검증 `통과`
- 안전 경계:
  - 실제 성과 회고 아님
  - 투자 판단 평가나 권유 아님
  - 화면용 가상 결과

## 1순위: 에이전트별 역할 상태판

- 목적: 제안자, 검증자, 정책 감시자, 승인 관리자 등 역할이 현재 어떤 상태인지 보여준다.
- 이유: 프로젝트 핵심 컨셉인 역할 분리와 독립 검증 구조를 제품 화면 안에서도 더 선명하게 보여줄 수 있다.
- 주요 구성 후보:
  - 역할별 현재 상태
  - 마지막 작업과 대기 사유
  - 충돌·반려·검증 실패 이력
  - 사용자 승인이 필요한 항목
  - 실제 자동 실행이 아니라 화면용 상태임을 표시
- 안전 경계:
  - 실제 AI 실행 상태 아님
  - 외부 에이전트·API 연결 없음
  - 사용자의 승인 없이 어떤 금융 행동도 하지 않음

## 2순위: 포트폴리오 변경 전/후 비교

- 목적: 리밸런싱이나 승인 전후의 가상 포트폴리오 변화를 비교한다.
- 이유: 제안 화면과 승인 화면은 있지만, 변경 전후의 위험·비중·현금 변화 비교를 한 화면에서 보는 뷰는 아직 없다.
- 주요 구성 후보:
  - 현재 비중과 변경 후 비중
  - 현금 비중 변화
  - 예상 위험 변화
  - 관련 정책 위반 여부
  - 승인 대기 화면으로 이동하는 링크
- 안전 경계:
  - 변경 후 수치는 실제 체결 결과 아님
  - 실제 주문 생성 아님
  - 손실 회피나 수익 개선 보장 아님

## 추천

다음 기획의 기본 추천은 `에이전트별 역할 상태판`이다. 사용자 결정 회고는 `MOCKUP-016`으로 완료됐으므로, 다음에는 제안자·검증자·정책 감시자·승인 관리자 역할 분리를 제품 화면 안에서 더 선명하게 보여주는 흐름이 자연스럽다.
